# Plan: per-target term and type homs on metavar and nonterminal primary roots

Claude: this note is written by Claude (Opus 5), from a reading of the Ott
sources at commit a89567b on branch lean-experiment, 2026-09-13.  Every claim
about current behaviour below was checked against the code or against output
generated by `bin/ott` at that commit; the line numbers are from that commit.

## 1. What is wanted

For a metavar or nonterminal **primary root**, and for each target
`TGT` in {`coq`, `hol`, `isa`, `lem`, `lean`, `ocaml`, `twf`, `tex`}, the
grammar should be able to declare two things independently:

- `{{ TGT <ident> }}` — the identifier to use where the root appears in a
  **term** position of the generated output: bound variable names, the
  components Ott builds function names out of, constructor argument names;
- `{{ TGT-type <ident> }}` — the identifier to use where the root appears in
  a **type** position: the type definition it generates, type annotations,
  constructor argument types, and the type names Ott composes from roots.

The two are different identifier spaces in every target, and in some targets
they have incompatible lexical requirements: OCaml wants `typ` for a type and
`S5`-free lowercase for values; HOL reserves `T` for truth so a type called
`T` is a bad idea while term identifiers spelled `T` are fine.

## 2. What exists today

There are five distinct hom axes in play.  They are easy to confuse, so this
section states each one precisely.

| axis | where written | where read | meaning |
|---|---|---|---|
| nonterminal per-name hom | `rule_ntr_names` (`T {{ hol Typ }}, S, U :: 'Ty_' ::=`) | `pp_nonterm_with_sie_internal`, `src/grammar_pp.ml:987` | how that nonterminal name prints |
| metavar per-name hom | `mvd_names` | `pp_metavar_with_sie_internal`, `src/grammar_pp.ml:1054` | how that metavar name prints |
| metavar representation | `mvd_rep` (`metavar x ::= {{ coq nat }}`) | `pp_metavarrep`, `src/grammar_pp.ml:1367`, emitted by `pp_metavardefn`, `src/grammar_pp.ml:1279` | the **type** the metavar is defined to be (`Definition termvar := nat.`) |
| `TGTvar` hom | `mvd_rep` (`{{ ocamlvar "[[x]]" }}`) | `pp_variable`, `src/grammar_pp.ml:3170` | how a concrete variable *value* prints |
| target renaming | none — mechanical | `caml_rename` / `twelf_rename`, `src/auxl.ml:1562`, `src/auxl.ml:1568` | case-folds every root and production name for OCaml/Twelf |

The `-type` mechanism already exists generically in `Auxl`:

```ocaml
let hom_spec_for_pp_mode m homs =                    (* src/auxl.ml:632 *)
  hom_spec_for_hom_name (hom_name_for_pp_mode m) homs
let hom_spec_for_pp_mode_dash_type m homs =          (* src/auxl.ml:634 *)
  hom_spec_for_hom_name (hom_name_for_pp_mode m ^ "-type") homs
```

and `pp_nonterm_with_sie_internal` already switches on the `as_type` flag
(`src/grammar_pp.ml:1000`):

```ocaml
let hso =
  if as_type then Auxl.hom_spec_for_pp_mode_dash_type m homs
  else            Auxl.hom_spec_for_pp_mode m homs in
```

So for nonterminals the shape of what is wanted is in place.  Four things are
missing or wrong.

**(a) There is no fallback between the two.**  In a type position, if there is
no `TGT-type` hom, `hso` is `None` and the bare root is printed — the `TGT`
hom is *not* consulted.  The visible consequence, in `tests/test7.ott`, which
declares

```
T {{ hol Typ }} {{ lean-type Typ }}, S, U :: 'Ty_' ::=
```

is that the HOL output still names the type `T`:

```
T =  (* type *)
   Ty_Var of typevar
 | Ty_Fun of T => T
```

while the Lean output, which has the `-type` spelling, correctly says
`inductive Typ`.  `{{ hol Typ }}` has been in `tests/test7.ott` (and 18 other
files) since the original import and has never had the effect its author
plainly intended.

**(b) The typechecker rejects every `TGT-type` but `lean-type`.**
`allowable_hom_data`'s `Hu_root` entry (`src/grammar_typecheck.ml:406`) lists
`isa coq lean lean-type hol lem tex ocaml`.  Writing `{{ hol-type Typ }}`
today is an error, so (a) cannot even be worked around by hand.

**(c) Metavars never consult the `-type` hom at all.**
`pp_metavar_with_sie_internal` (`src/grammar_pp.ml:1054`) uses
`hom_spec_for_pp_mode` unconditionally.  The single place `as_type` matters
for a metavar is the phantom special case a few lines above it, which prints
the `mvd_rep` hom.  So a metavar root cannot be named differently in type and
term positions in any target.

**(d) For OCaml and Twelf the homs are overridden by the renaming passes.**
`caml_rename` (`src/auxl.ml:1562`) capitalises every production name and
uncapitalises every primary nonterminal and metavar root, consulting no homs,
and raises an error if the fold makes two names collide.  Whatever a root hom
says, the OCaml output uses the folded name; and a grammar that uses case to
distinguish two things (`tests/test7.ott` has both `T` and `t`, and both
`xinG` and `XinG`) cannot be generated for OCaml at all.

## 3. Proposed semantics

For a primary root `R` with per-name homs `homs`, printing for mode `m` with
target name `TGT = hom_name_for_pp_mode m`:

- **term position** (`as_type = false`): `{{ TGT ... }}` if present, else `R`
  (modulo the existing Twelf capitalisation).
- **type position** (`as_type = true`): `{{ TGT-type ... }}` if present, else
  `{{ TGT ... }}` if present, else `R`.

The fallback in the type case is the whole of the behavioural change.  It
makes `{{ hol Typ }}` mean "call this `Typ` in HOL", which is what every
existing use of it intends, and leaves `{{ lean-type Typ }}` meaning "call
this `Typ` in Lean types only".  A grammar that genuinely wants a different
spelling in the two positions writes both homs.

The same rule applies to metavar per-name homs.  Three things deliberately do
**not** change:

- `mvd_rep` keeps its present meaning: `metavar x ::= {{ coq nat }}` still
  says the representation type is `nat`.  It is a different axis from the
  root's *name*, and overloading it would break every existing file.  A
  `-type` hom for a metavar goes on the name list, exactly as for a
  nonterminal.
- `TGTvar` homs keep their present meaning (rendering of a variable value).
- The Twelf capitalisation in `capitalize_if_twelf_non_type`
  (`src/grammar_pp.ml:1007`) stays as the fallback when no hom applies.

### Where "type position" is decided

`as_type` is set by the two entry points `pp_nontermroot_ty`
(`src/grammar_pp.ml:1233`) and `pp_metavarroot_ty` (`src/grammar_pp.ml:1236`),
and through `pp_nt_or_mv_root_ty` (`src/grammar_pp.ml:1249`).  Anything
reached through those is a type position, which includes the composed type
names: `Transform.expand_element` builds `list_<root>_<root>` from
`pp_nt_or_mv_root_ty` (`src/transform.ml:131`), so the Coq list helper types
follow the `-type` names automatically.  This is the right answer — those
identifiers name types — and it is worth stating in the manual, because it
means changing a `-type` hom renames `list_label_t` and friends.

## 4. Implementation

Each step is small and separately testable.

1. **One lookup function.**  In `src/auxl.ml`, next to the two existing
   helpers at 632-635:

   ```ocaml
   let hom_spec_for_root as_type m homs =
     if as_type then
       match hom_spec_for_pp_mode_dash_type m homs with
       | Some hs -> Some hs
       | None -> hom_spec_for_pp_mode m homs
     else hom_spec_for_pp_mode m homs
   ```

2. **Nonterminals.**  Replace the `if as_type then ... else ...` at
   `src/grammar_pp.ml:1000-1006` with a call to it.  This alone implements the
   fallback of item (a).

3. **Metavars.**  In `pp_metavar_with_sie_internal`
   (`src/grammar_pp.ml:1054`), replace `Auxl.hom_spec_for_pp_mode m homs` with
   the same call, leaving the phantom/`mvd_rep` case ahead of it untouched.
   This implements item (c).

4. **Typechecker.**  In `src/grammar_typecheck.ml`, extend `Hu_root` (line
   406) with `TGT-type` for every target, and check `Hu_metavar` (409) and
   `Hu_rule` (411) for the same, since root homs can be written in all three
   positions.  This implements item (b).

5. **Validate the hom body.**  A root hom should be a single
   `Hom_string` naming an identifier.  Today a `[[...]]` index inside one is
   accepted and produces nonsense downstream.  Add a check where the hom is
   converted (`cd_hom`), reporting the location.  Cheap, and it turns a silent
   mis-generation into a diagnostic.

6. **Lexer keyword list.**  `hom_strings` in `src/grammar_lexer.mll:65` is
   only used to set `\mykw` in the TeX rendering of Ott sources; add the new
   names so they render like the others.  No semantic effect.

7. **Manual.**  `doc/top2.mng` has the hom tables; the root table is the one
   listing `isa`/`coq`/`hol`/`ocaml`/`tex`.  Document both spellings and the
   fallback, and note the effect on composed type names from step 3's
   discussion.

## 5. The OCaml and Twelf renamers

Item (d) is a separate and larger piece of work, and it is a prerequisite for
the `ocaml` and `twf` halves of this plan being meaningful: until it is done, a
root hom for those targets is silently overridden by the case fold.

- `capitalize_prodnames` (`src/auxl.ml:1525`),
  `uncapitalize_primary_nontermroots` (1544) and
  `uncapitalize_primary_metavarroots` (1553) should compute each new name from
  the relevant root hom when one is present, and fold case only as the
  default.  The collision check then runs on the *resulting* names, so a
  grammar can resolve a collision by naming one of the two.
- Two latent bugs in the renaming machinery must be fixed at the same time;
  both were confirmed by experiment on 2026-09-13, and both are invisible
  today only because the case fold is the identity on the lowercase grammars
  in the regression suite:
  - `rename_structure_entry` returns `Struct_sbs xs` and `Struct_fvs xs`
    unrenamed while `rename_syntaxdefn` renames `xd_sbs` and `xd_fvs`, so
    `System_pp.pp_struct_entry`'s `List.find` raises, and Ott dies with an
    uncaught `Fatal error: exception Not_found` rather than a diagnostic.
  - `rename_freevar` renames `fv_that` but not `fv_this`, unlike
    `rename_subst` beside it, which breaks the same lookup from the other end.
- Even with all of that, OCaml needs lowercase **value** identifiers, and the
  renaming maps cover only primary roots: non-primary names (`S`, `U`, `X`)
  reach OCaml value positions unchanged, as do substitution and free-variable
  function names (`Tsubst`).  Generating `tests/test7.ott` for OCaml produced
  `let rec Tsubst_typ (S5:typ) (X5:typevar) ...`, which `ocamlc` rejects.
  Fixing that means extending the renaming to every name in `rule_ntr_names`
  and `mvd_names` and to `sb_name`/`fv_name`, with conflict handling.  It is
  out of scope here but should be tracked as the follow-on.

## 6. Compatibility, and what to measure

- A file with no root homs cannot change: every new lookup falls through to
  the present behaviour.
- A file **with** a root hom can change in type positions, because of the new
  fallback.  19 files under `tests/` and `examples/` carry a root rename of
  this shape, nearly all of them `T {{ hol Typ }}, S, U :: 'T_' ::=`.  For
  those the HOL type name becomes `Typ` instead of `T`.  That is the intended
  fix, and it is very likely a correctness improvement (HOL's `T` is truth),
  but it must be looked at rather than assumed: the HOL column of the
  regression currently fails everywhere in this environment because no
  Isabelle/HOL is installed, so the check has to be by reading the generated
  `.sml` files, not by the pass/fail columns.
- Measurement procedure, which works well:
  `./regression -all -todo_list regression.otl -temp_dir <dir> -keep_temp`
  before and after, then `./regression -compare_reports` for the columns and
  `./regression -compare_ott_generated_files <dirA> <dirB>` for the files.
  The second is the useful one: it is a byte comparison over every generated
  file, so the intended changes can be enumerated and inspected.
  Note that the temp dir and the source paths must not contain the two
  characters `/-`, or every generated Lean file is broken: Lean block comments
  nest, and the path is printed inside the `/- generated by Ott ... -/` header.

## 7. Tests

- A new `tests/test_root_homs_1.ott` declaring one nonterminal and one metavar
  that carry both homs for several targets, with productions that exercise:
  the type definition, a constructor argument type, a substitution function
  name, a subrule predicate name, and a list of pairs (so that the composed
  `list_..._...` name is covered).  Check the generated Coq, HOL, Isabelle,
  Lem and Lean by inspection once, then keep them as the regression baseline.
- A negative test for step 5's validation: a root hom containing `[[...]]`
  should be an error with a location, not silent nonsense.
- `tests/test7.ott` is the natural real-world case: once the fallback lands,
  its HOL output should use `Typ` throughout, and `{{ lean-type Typ }}` can
  stay as it is or be paired with a `{{ lean Typ }}`.

## 8. Suggested commit sequence

1. `Auxl.hom_spec_for_root` plus the two printer call sites (steps 1-3) —
   the behavioural change, measured as in section 6.
2. Typechecker allowable lists and the hom-body validation (steps 4-5).
3. Lexer keyword list and manual (steps 6-7).
4. New tests, and any `.ott` files updated to use the new spellings.
5. Separately, on its own branch: the renamer work of section 5, starting with
   the two latent bugs, which are worth fixing on their own account.

## 9. Open questions

- **Is the type-position fallback the right default?**  It is what makes the
  19 existing `{{ hol Typ }}` uses work, but it is a change in behaviour for
  them.  The alternative — keep the two independent and require every file to
  write `hol-type` — is more explicit and changes nothing, at the cost of
  leaving those files silently wrong until each is edited.  This note assumes
  the fallback; it is the one decision to take before starting.
- **Non-primary names.**  The printers look up per-*name* homs, so `S` and `U`
  can already carry their own homs and would gain `-type` for free.  Worth
  saying so in the manual, and worth deciding whether the renamers should
  respect them too (section 5 says they must, for OCaml).
- **`tex`.**  TeX has its own established mechanisms (`texvar`, the per-rule
  hom applied through `apply_hom_spec`) and a type/term distinction is not
  obviously meaningful there.  Suggest accepting `tex-type` for uniformity but
  documenting it as having no separate effect, or leaving `tex` out entirely.
- **`twf`.**  The Twelf backend has its own capitalisation rule
  (`capitalize_if_twelf_non_type`) which is already keyed on `as_type`; the
  interaction with an explicit hom needs one paragraph of thought before
  implementing.
